# 心晴 · 产品体验迭代版

## 本次完成
- 本机草稿即时保存及刷新恢复；草稿不上传云端。
- 历史记录编辑、文字与标签搜索；修改保存更新时间。
- 保存后清空心情、标签及文字，减少误带入。
- 洞察增加记录数、记录天数、平均心情；少于三个记录日不推断稳定规律。
- 登录与同步成功分开显示；移除“永久保存”承诺。
- 新增隐私及支持说明，明确规则建议不是 AI 诊断，音景是合成模拟。
- 保留七种音景、静谧视觉、登录框及日期布局修复。

## GitHub Pages 部署
1. 先在旧网页“历史记录”导出 JSON 备份，并妥善保管，不要上传公开仓库。
2. 解压本压缩包。将 index.html、style.css、app.js、config.js、cloud-sync.js 五个文件一起覆盖仓库根目录同名文件。不要把外层文件夹上传，也不要只上传 ZIP。
3. 沿用原有 Pages 设置。本次不要求修改 Supabase 数据库结构。
4. 等待仓库部署任务成功，在原网址强制刷新。必须沿用原域名及浏览器才能读取原本机记录。
5. 配置文件保留已有项目地址和公开密钥；不得放入 service_role 或 secret key。

## 部署验收
- 输入草稿并选择心情，刷新后可恢复；保存后只增加一条，表单复位。
- 编辑历史记录后数量不增加；搜索文字和标签有效。
- 手机窄屏及浏览器缩放后日期与登录按钮无覆盖。
- 七种音景可开始、停止、切换；这不是实地录音。
- 用测试日记完成邮箱登录，并在另一台设备核对同步结果。
- 在 Supabase 核对 RLS 已启用且不同账号不能读取或修改对方数据。未完成此项不要公开邀请用户。

## 已知限制：个人试用版，不是成熟心理健康服务
- 线上网页本次无法通过检索工具打开；结论基于交付源码和用户截图。
- 当前推荐是规则匹配，没有接入大语言模型，不能作心理诊断。
- 多账号共用浏览器的本地数据隔离、退出登录后的本机残留尚未解决，请仅在私人设备用同一账号试用。
- 云端同步仍需加强：持久化离线操作队列、删除重试、并发合并与冲突恢复。离线删除可能在再次同步后重新出现；同步期间修改可能冲突。
- 本地存储并非加密保险箱，未提供端到端加密；清除浏览器数据可能丢失未同步记录。
- 图表目前按有记录的日期排列，缺失日期不代表平静；心情均值是自报信息，不是健康分数。
- 音景只是噪声与振荡器模拟，部分选项相似；后续可引入有明确授权的自然录音并试听验收。

## 产品经理判断与后续路线
定位：低压力的私人记录空间。核心体验是“愿意写 → 不丢失 → 能回看 → 得到一点帮助”，不是打卡竞争或心理诊断。

P0：首先完成账号隔离、离线同步及权限测试，然后再邀请外部用户。避免“永久”“绝对安全”等未经保障的承诺。

P1：完善情绪表达（混合感受、自定义标签）、按真实日期展示趋势、记录后可选的一步关怀。暂不加入连续打卡惩罚或排名。

P2：AI 仅作为可选的反思助手，默认不上传日记。接入前需要独立授权、服务端密钥保护、数据保留说明、删除机制、安全输出约束及测试集；不建议自动诊断或替用户断定情绪原因。

评估指标建议：首次记录完成率、保存成功率、草稿恢复成功率、同步失败率、七天内主动回访率，以及关怀后用户自报“是否有帮助”。当前未接入埋点，不收集日记正文用于分析。
